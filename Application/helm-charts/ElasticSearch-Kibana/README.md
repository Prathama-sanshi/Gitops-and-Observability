# Fluentbit ConfigMap: Service,Input, Parser, Filter, and Output

## 1. [SERVICE]
The [SERVICE] block defines the global runtime engine settings for the entire Fluent Bit daemon process.

```text

[SERVICE]
    Flush        1      #flush (ship) its memory log buffers to your output engine (Elasticsearch) every 1 second
    Log_Level    info  `#set the logging level to info for Fluent Bit
    Parsers_File /fluent-bit/etc/parsers.conf   #specify the path to the parsers configuration file
```

## 2. [INPUT]
It configures the data collection engine (the harvester) to track files on your system and pass them into the processing pipeline.

```text
[INPUT]
    Name         tail   #use the tail input plugin to monitor files
    Path         /app/logs/*.log      #specify the path to the log files
    Tag          app.layered    #specify the custom tag for the log files
    DB           /app/logs/fluent-bit-tail.db    #specify the path to the database file[records file pointer]
    Parser       stage1_text_extractor    #specify the path to the parser configuration file
    Mem_Buf_Limit 5MB    #specify the memory buffer limit(buffer space)
```

## 3. [PARSER]
The regular expression tells Fluent Bit how to slice up your raw text line using Named Capture Groups ```(?<field_name>pattern)```

Lets take an example:

App Log example: ```2026-09-14 09:07:28,351 [INFO] [Deleter] Deleted: file_4709.txt```

```text
[PARSER]
    Name        stage1_text_extractor
    Format      regex
    # This Regex extracts date, time, log_level, and log_message fields verbatim
    Regex       ^(?<date>\d{4}-\d{2}-\d{2}) (?<time>\d{2}:\d{2}:\d{2},\d{3}) (?<log_level>\[[A-Z]+\]) (?<log_message>.*)$
    Time_Key    time
    Time_Format %H:%M:%S,%L
```

 * Step: 1
    ```^(?<date>\d{4}-\d{2}-\d{2})``` : Looks at the start of the line (^) and extracts 4 digits, a hyphen, 2 digits, a hyphen, and 2 digits. It names this key **date**

* Step: 2
    ```(?<time>\d{2}:\d{2}:\d{2},\d{3})``` : Bypasses the space and extracts your hours, minutes, seconds, and milliseconds (09:07:28,351). It names this key **time**.

* Step: 3
    ```(?<log_level>\[[A-Z]+\])``` : Bypasses the next space and captures anything in capital letters enclosed in brackets ([INFO]). It names this key **log_level**

* Step: 4
    ```(?<log_message>.*)$``` : Bypasses the last space and scoops up everything remaining until the end of the line ($). It names this key log_message. **log_message**.

# 4. [OUTPUT]:
The [OUTPUT] block defines the final destination of your data pipeline. It takes the fully processed, structured JSON log entries and packages them into bulk network payloads to send directly to your Elasticsearch cluster over the network

```text
[OUTPUT]
    Name            es      # This plugin natively handles bulk HTTP POST requests
    Match           app.layered     #Tells this specific output destination to only grab log entries that carry the internal tag app.layered
    Host            {{ .Values.elasticsearch.host }}    #Specifies the hostname or IP address of your Elasticsearch cluster
    Port            {{ .Values.elasticsearch.port | quote }}    #Specifies the port number on which your Elasticsearch cluster is listening for incoming HTTP requests
    Logstash_Format On    #Enables the Logstash-style JSON format for the bulk request payload
    Logstash_Prefix {{ .Values.elasticsearch.logstashPrefix }}    #Specifies the prefix for the index name in Elasticsearch
    Suppress_Type_Name On 
```

-   Elasticsearch stores this document under a specific daily index partition generated by your output settings.

- Target Index Name: app-logs-2026.09.14(Formed automatically because Logstash_Format is On and Logstash_Prefix evaluates to app-logs).

# Kibana Results
* Elasticsearch separates the data into two entirely different layers: ```_source``` (how the data was received) and ```fields``` (how the data is indexed for searching and analytical graphs).
* 1] ```_source```:
  - The _source object contains the exact, unaltered JSON document that Fluent Bit sidecar container packaged and shipped.
* 2] ```fields```:
    * The fields block is generated dynamically by Elasticsearch's search engine when you run a query.The fields block is generated dynamically and used explicitly by Kibana (and other API clients) as a high-performance reference layer to build your charts, timelines, and search filters
